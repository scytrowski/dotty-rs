# Source control flow and the TASTy boundary

This note records the source-side semantic contract and the independent Scala
3.9.0 wire shape for the small control-flow forms audited by issue #1309. The
wire fixtures in `tests/fixtures/tasty_pickler` are generated by the pinned
Scala compiler at revision `777528f19a58e794c9954a42f433373472ec57f8`; they are
not output from the Rust pickler. The production pickler remains outside this
change.

## Audited source forms

| Scala source | SourceTyper contract | Scala 3.9 TASTy observation |
| --- | --- | --- |
| `def unit: Unit = ()` | The RHS is a typed `Literal(Constant::Unit)` with `Type::Constant(Unit)`; the declared result is canonical `Definitions.unit`. | The RHS is `UNITconst`. |
| `def enabled: Boolean = true` / `disabled = false` | Boolean literal RHSs retain their `Type::Constant(Boolean(value))`; declared Boolean results and Boolean formals use canonical `Definitions.boolean`. Parameterless methods have the result type directly, with no empty value clause. | `TRUEconst` / `FALSEconst`; Boolean result and parameter types are `TYPEREF`s to `scala.Boolean`. |
| `if flag then a else b` | The source root maps to a typed `TreeKind::If`. Its condition is typed against Boolean. Branch references preserve their formal `SymbolId`s. The `If` type is canonical Int after branch widening and joining. | `IF` children are condition, then branch, else branch in that wire order. |
| Nested `if` | Each source `If` has its own source-to-typed mapping. The nested and outer result types are canonical Int for the audited literal branches. | An `IF` child can itself be `IF`; each node keeps condition/then/else order. |
| `{ if flag then 1 else 2; value }` | The source and typed blocks each retain the discarded `If` as their first stat and `value` as the final expression. The stat keeps its Int type; statement position discards its value without replacing the node with Unit. The block result type is Int. | `BLOCK` stores its result expression first, then stats in source order. Thus `value` precedes the discarded `IF` in the wire children. |
| `{ val saved: Int = value; if flag then saved else 0 }` | `typed_local_binding_at(source, val_tree)` returns the exact typed `ValDef` and canonical local symbol. The method owns that local symbol; the `saved` branch reference has a `Type::TermRef` targeting the same symbol. The block has one typed `ValDef` stat and an `If` expression. | `BLOCK` stores the result expression first and `VALDEF(saved)` as a stat afterward. The expression root is a `TYPED` wrapper whose child is the `IF`. The `TERMREFdirect` for `saved` targets that exact `VALDEF` node, even though its target follows the reference in wire order. |
| `{ var count: Int = value; count = count + 1; count }` | The read-only local binding identifies the method-owned `SymbolId` and exact typed declaration. Source `var` syntax and canonical `MUTABLE` flag must agree. `Assign` maps by exact source/typed root and child bindings, targets that visible mutable local, has an Int RHS, and has canonical Unit type. | The `VALDEF` carries the Scala 3.9 `MUTABLE` modifier. `BLOCK` stores its final `count` reference first, then `VALDEF(count)` and `ASSIGN` in source order. `ASSIGN` children are target then RHS; the direct target reference addresses the same `VALDEF`. |
| `while i < n do total = total + i; i = i + 1` | The source `While` maps to a typed `While` with its exact Boolean condition and Unit body children. Its result type is canonical Unit. In the audited form, the Unit body is a Block whose assignment stats remain ordered and whose final expression is the second assignment. | `WHILE` children are condition then body. The body `BLOCK` stores its final assignment first, then preceding assignment stats in source order; both `ASSIGN` nodes keep target-before-RHS ordering. |

The test-only source contract is `tests/tasty_control_flow_contract.rs`. It
parses and names the checked-in Scala fixtures, completes their source method
signatures, types the bodies with `SourceTyper`, and asserts the source/typed
tree mappings, canonical result and formal types, nested `If` structure,
block-stat order, and local declaration/reference identity. It does not build
or inspect a Rust-produced TASTy file.

The independent fixture snapshots separately pin the Scala output. Their
normalized `BLOCK` rows expose the expression root and ordered `stats`; the
expression root can be a `TYPED` wrapper. `IF` rows
expose `condition`, `then`, `else`, and `inline`; local `VALDEF` rows expose
their name, RHS presence, and modifiers; Boolean and Unit constants retain
their values. Node IDs preserve parent/owner relationships and all reference
targets while avoiding absolute wire offsets. The `.tasty` files retain the
original Scala bytes.

`tools/tasty-pickler-oracle/run.py check` regenerates those snapshots with the
pinned compiler, decompiles each Scala-produced fixture, asks Scala
`-from-tasty` to produce a fresh class, and runs corruption/truncation and
package-layout negative controls. It also compiles `Decisions.scala` directly
as source and runs the JVM reference harness, independently of the checked-in
TASTy. Expected source results are:

```text
unit()                  -> Unit
enabled(), disabled()   -> true, false
choose(true, 17, 42)    -> 17
choose(false, 17, 42)   -> 42
nested(true, true)      -> 1
nested(true, false)     -> 2
nested(false, true)     -> 3
stored(true, 17)        -> 17
stored(false, 17)       -> 0
```

The default Rust tests do not require Scala, a JDK, or network access. Run the
independent oracle explicitly with the pinned Scala checkout, JDK 21+, and
cached compiler artifacts described by `tools/tasty-pickler-oracle/README.md`.

## Future producer boundary

The following is the narrow source-to-TASTy acceptance boundary justified by
these fixtures and the existing shared semantic model. A producer increment
may accept ordinary class methods returning Unit, Boolean, or Int; ordinary
Boolean/Int value parameters; Boolean literals; `If` with supported Boolean
conditions and supported branch result types; recursively nested `If`; and
blocks with a final supported expression plus ordered supported stats. For a
local declaration, the audited case is an ordinary immutable Int `ValDef`
with an Int initializer and references resolved to its canonical local symbol.
The producer additionally accepts ordinary mutable Int `var` declarations and
`Assign` statements whose target is the same in-scope method-local symbol. It
also accepts typed `while` statements with a supported Boolean condition and a
Unit body consisting of ordered assignments. Only immutable ordinary `val` and
mutable ordinary `var` are accepted. Emission must follow the pinned wire
order above, preserve formal/local identity, and encode the `ValDef` as the
declaration target for local direct references.

Lazy, given, implicit, erased, inline, pattern, field, captured, and
local-method definitions remain unsupported; arbitrary local types;
arbitrary condition/operator expressions; unsupported branch joins; multiple
or contextual parameter clauses; or other block-stat forms. Such forms remain
explicitly unsupported until separately modeled, tested, and compared against
the pinned Scala oracle. In particular, method or branch names alone are not
semantic identities, and a producer must not synthesize a local reference by
name when its `SymbolId` or typed binding is missing.
