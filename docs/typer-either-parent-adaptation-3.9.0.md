# Generic source-parent adaptation for Either (Scala 3.9.0)

Issue #1727 adds a bounded rule for a generic source `this` when adapting its
declared parent views. A bare `ThisType` for a current source class is first
viewed as that class applied to its own canonical type parameters, in source
order. Existing exact-arity validation and symbol-based substitution then
instantiate the declared parent. Raw generic `TypeRef`s, external generic
classes, and malformed parent types remain unsupported.

## Coverage

The focused `Child[A, B] extends Parent[A, B]` regression checks that adapting
`Child.this` yields `Parent[Child.this.A, Child.this.B]`, with the original
parameter symbols owned by `Child` and preserved in order. Negative tests check
an unrelated receiver owner, a wrong receiver arity, and a malformed parent
shape. The wrong-arity and malformed-parent lookup failures assert that store
allocations and symbol completion are rolled back.

## Pinned source and method-gate result

The source checkout is pinned to Scala revision
`777528f19a58e794c9954a42f433373472ec57f8`; the Scala 3.9.0 compiler compiled
the eight source files selected by the ordinary-method cohort. Its typer output
confirms the exact roots are valid Scala methods:

- `Either.left: Either.LeftProjection[A, B]`
- `Either.right: Either.RightProjection[A, B]`
- `Either.swap: Either[B, A]` (edge control)

The deterministic ordinary-member audit selected and attempted all 25 methods
before and after this change. Both runs typed 10 and blocked 15; the 10 existing
typed methods retained their exact source-tree IDs, typed-tree IDs, and result
shapes. **Neither `left` nor `right` is fully typed yet.** Their first blocker
advanced from `ParentTypeAdaptation(RawGenericSourceReceiverUnsupported)` to
`MemberNotFound` at source trees 16 and 28, respectively. They have no typed
method tree or actual result, so this is progress through the parent-adaptation
stage, not method acceptance. The `swap` control remains blocked and advances
to an external module identity `SymbolResolution` for `scala.util.Left`.

The ordinary gate passes only its ten frozen `required_typed` rows; the exact
`left`/`right` rows remain observations and are reported separately here. The
full 25-method report is retained locally under the task build directory and
is regenerated by the command below; the repository-wide typer corpus was not
run.

## Reproduction

Use `SCALA39_ROOT` at the pinned checkout, `COURSIER_MAVEN_ROOT` with the Scala
3.9.0 artifacts, and `JAVA_HOME` for the installed JDK. Keep build and temporary
files under the worktree:

```sh
export CARGO_TARGET_DIR="$PWD/target/issue-1727/cargo"
export TMPDIR="$PWD/target/issue-1727/tmp"
export DOTTY_AUDIT_TMP_ROOT="$PWD/target/issue-1727/audit-tmp"
export CARGO_BUILD_JOBS=1
export RUST_TEST_THREADS=1

tools/typer-classpath-corpus-audit/run \
  --method-kind ordinary \
  --method-manifest docs/typer-stdlib-minimal-method-cohort-3.9.0.tsv \
  --require-typed-cohort docs/typer-stdlib-minimal-method-cohort-3.9.0.tsv \
  --verify-determinism target/issue-1727/ordinary-after.tsv
```

The local environment had Corretto JDK 25.0.4, so the local oracle/audit used
that JDK with release 25. The hosted repository gates provide the JDK 21
validation. The Scala source revision and compiler/library artifacts remained
pinned in the local run.
