# Scala 3.9 class fields and primary-constructor TASTy contract

This is an oracle and source-semantic audit for issue [#1389](https://github.com/scytrowski/dotty-rs/issues/1389). It does not add a TASTy producer feature. The checked-in Scala inputs, Scala-generated TASTy files, normalized snapshots, compiler hashes, JDK identity and generation command are pinned in [`provenance.json`](../tests/fixtures/tasty_pickler/provenance.json). Recreate or verify them offline with:

```sh
SCALA39_ROOT=/path/to/scala3-at-777528f19a58e794c9954a42f433373472ec57f8 \
JAVA_HOME=/path/to/jdk-21 \
COURSIER_MAVEN_ROOT=/path/to/cached-maven2 \
python3 tools/tasty-pickler-oracle/run.py generate --check
```

The compiler is Scala 3.9.0 at revision `777528f19a58e794c9954a42f433373472ec57f8`; emitted files report TASTy 28.9.0. The oracle recompiles the fixtures into a fresh directory, compares normalized trees, runs the Rust wire inspector, decompiles every artifact, and invokes Scala `-from-tasty` without adjacent source or class files. The `Counter.tasty` gate also executes the fresh class for constructor initialization, reads, writes and increments. It establishes Scala-reader interoperability for Scala-generated bytes, not Rust producer support.

## Observed fixture grammar

`PrivateValues.scala`, `MutableField.scala`, `Box.scala` and `Counter.scala` are deliberately separate inputs. Their complete trees are in [`snapshots/example/`](../tests/fixtures/tasty_pickler/snapshots/example/); corresponding original wire files are in [`tasty/example/`](../tests/fixtures/tasty_pickler/tasty/example/).

| Source form | Observed TASTy 28.9 shape |
| --- | --- |
| `private val seed: Int = 42` and `private val enabled: Boolean = true` | Class `TYPEDEF` contains a `TEMPLATE`; after its Object parent call and no-argument `<init>`, each source member is a class-owned `VALDEF` with an explicit `IDENTtpt`, literal RHS, and modifier bytes `PRIVATE (6), LOCAL (22)`. The synthesized constructor has an `EMPTYCLAUSE`, Unit result, no RHS, and no modifier tail in this fixture. There is no `DEFDEF seed`/`enabled` or generated backing-field declaration in this pickle. |
| `private var current: Int = 0` | Class-owned `VALDEF` with `PRIVATE (6), LOCAL (22), MUTABLE (25)`, an `Int` type tree, and literal RHS. User-authored `get`, `set`, and `increment` remain ordered `DEFDEF`s. No synthetic `current` getter or `current_=` setter appears in the pickled template. |
| `class Box(start: Int)` | The `TEMPLATE` begins with a class-owned `PARAM start`, then the parent call, then `<init>` with a separate constructor-owned `PARAM start` and a Unit result tree. The constructor has the observed `STABLE (32)` marker. There is no `VALDEF start`; this plain parameter is not a source field/accessor. |
| `Counter(start: Int)` with `private var current = start` | Same two distinct `PARAM start` declarations as `Box`, but the constructor has no `STABLE` marker in this fixture. `current` is a `VALDEF`; its RHS is `TERMREFsymbol` whose reference target is the **template/class-owned** `PARAM start`, not the constructor-owned `PARAM`. `get` reads `current` as `SELECT(QUALTHIS(...))`. `set` writes `ASSIGN(SELECT(QUALTHIS(...)), TERMREFdirect(value))`. `increment` is a source-order `BLOCK` containing the assignment and final read; the addition is `APPLY(SELECTin(Int.+), ...)`. |

The raw modifier labels above are the exact Scala 3.9 wire tags. The oracle inspector intentionally preserves currently unnamed tags as `tag-N`, so snapshots do not silently reinterpret their meanings. `TEMPLATE` children are ordered: a parameter prefix when present, parent construction, constructor definition, then source members. `DEFDEF` parameter declarations belong to the method/constructor node; they are not aliases for same-named template parameters. The `TYPEDEF` also carries the compiler-injected `SourceFile` annotation, preserved in the normalized snapshots. Constructor markers are fixture-specific: the private-val default constructor has no `STABLE` tail, while `Box` has it; do not generalize the `Answer`-fixture marker to every constructor.

## Source semantic identity and the TASTy phase boundary

The test-only Lexer → Parser → Namer → SourceTyper fixture establishes different but related identities before serialization:

| Source entity | Canonical/derived source identity | Typed or wire edge |
| --- | --- | --- |
| `Counter` | Canonical class `SymbolId`; its declaration scope is the class scope. | Structural `TYPEDEF` owner for the template and declarations. |
| `current` | Canonical `SymbolKind::Field`, owner `Counter`, `Visibility::Private`, `MUTABLE`; its source tree is the `ValDef` in `Template.body`. | The initializer root is indexed by `SourceTypedIndex`; typed reads and assignment targets retain the same field `SymbolId`. In serialized TASTy, reads/writes are name-bearing `SELECT`s, not references to a wire address for this source field. |
| plain constructor `start` | The parameter source tree has a class-owned canonical parameter identity. `derived_symbol_at(primary_constructor, source, tree)` returns a different constructor-owned parameter identity. | SourceTyper's typed field-initializer RHS is a `TermRef` to the derived constructor-owned parameter. Scala's pickled initializer instead targets its template-level `PARAM start`. This is an observed phase adaptation, not an identity that may be reconstructed by matching the spelling `start`. |
| primary constructor | Canonical constructor `SymbolId`; one ordered source clause with one `Int` parameter; completed semantic signature is `Type::Method` whose result references `Counter`. | `DEFDEF <init>` repeats the parameter under the constructor and uses a Unit return tree. It carries no user RHS in the fixture. |

The pinned [`Compiler` phase list](https://github.com/scala/scala3/blob/777528f19a58e794c9954a42f433373472ec57f8/compiler/src/dotty/tools/dotc/Compiler.scala) places `Pickler` after the frontend and before the transformation phases. Its [`Getters` phase](https://github.com/scala/scala3/blob/777528f19a58e794c9954a42f433373472ec57f8/compiler/src/dotty/tools/dotc/transform/Getters.scala) rewrites many class `ValDef`s into accessor `DefDef`s, while [`Memoize`](https://github.com/scala/scala3/blob/777528f19a58e794c9954a42f433373472ec57f8/compiler/src/dotty/tools/dotc/transform/Memoize.scala) can later introduce private storage. The source and pickled declaration must therefore not be equated with a final JVM backing field or accessor layout. The pinned [`TreePickler`](https://github.com/scala/scala3/blob/777528f19a58e794c9954a42f433373472ec57f8/compiler/src/dotty/tools/dotc/core/tasty/TreePickler.scala) also serializes separate template parameter prefixes and constructor parameters. These links are pinned to the same compiler revision as the fixture provenance.

## Source behavior, negative cases and limits

The Scala source oracle rejects duplicate class members, a concrete field without an initializer, and an `Int` field initialized by `Boolean`. The SourceTyper contract separately checks that a well-typed earlier-field read keeps its canonical field ID and that wrong initializer type returns `ExpectedExpressionTypeMismatch`. Successful field-initializer typing is **not** evidence that the field is initialized safely at runtime: self/forward references and cross-field initialization order need a separate initialization analysis. The test does not certify runtime order from a typed RHS.

The producer target here includes only private primitive `val`/`var`, the default constructor, and one plain `Int` parameter. Public/protected fields, `private[this]`, lazy fields, missing or ill-typed initializers, duplicate names, secondary/using/default/multiple-clause constructors, constructor `val`/`var` accessors, inheritance, generic/reference fields and companions are not in the producer contract. The fixtures characterize the source and wire shapes; they do not broaden the existing pickler plan, semantic unpickler, or JVM class emitter.

| Validation stage | Success means | It does not mean |
| --- | --- | --- |
| Rust wire inspector and normalized snapshot | This Scala-generated file has valid supported wire structure and the checked tree/edges. | A Rust-produced equivalent exists or has semantic identity parity. |
| SourceTyper test | The exact source declaration and initializer type in the tested frontend session; the root and referenced `SymbolId`s are indexed. | Initialization order is safe or a pickler plan may infer missing metadata. |
| Scala decompiler and `-from-tasty` | Scala 3.9.0 can read these Scala-generated fixture files and emit a fresh class. | The Rust encoder emits equivalent bytes or a general source construct is supported. |
| Counter runtime harness | The fresh class produced from Scala-generated TASTy preserves this fixture's constructor initialization and method behavior. | Rust JVM field layout, access flags, slots, `Fieldref`s, or Rust-generated class behavior. |

Follow-up pickler work must use canonical class/field/constructor/parameter IDs and the observed owner-specific parameter adaptation. It must state a bounded field/accessor representation and reject unsupported visibility, initialization, or constructor forms with explicit typed errors. Neither symbol lookup nor wire-edge synthesis may rely on names alone, and no JVM storage or ABI rule follows solely from these Scala TASTy snapshots.

## Plan validation boundary (#1390)

`ClassStatePicklePlan` is an additive, read-only input contract for the next
pickler increments. Its `members` slice preserves `Template.body` order as
explicit `Field` and `Method` entries. Validation checks every source tree and
canonical symbol against the source index, owner, `ClassInfo.declarations`,
class scope, completed type, visibility, flags, and field source modifiers.
The caller supplies the exact typed initializer `TreeId<Typed>` and a
`SourceTypedBindings` view; validation requires the index mapping and matching
source/typed spans. No AST or semantic record is cloned into another field
model.

The constructor contract permits the ordinary default form or one plain clause
of `Int` parameters. Parameter entries are the constructor-owned derived IDs in
source order; each must match `derived_symbol_at`, remain distinct from the
class-owned canonical parameter ID, and agree with the completed `Type::Method`
signature. The source parameter metadata must identify the parser's plain
`ParamAccessor + PrivateLocal` form; explicit `val`/`var` accessor forms remain
rejected. Field initializers in this increment are limited to matching
primitive literals or a direct reference to one of those constructor-owned
parameters. Field-to-field reads are rejected because successful typing alone
does not establish safe initialization order.

This plan has no TASTy serializer entry point. Existing `PicklePlan` validation
and emitted files remain unchanged; #1390 does not claim field or constructor
encoding support. Validation borrows the compilation session and cannot publish
bytes or mutate its semantic store. Unsupported or inconsistent inputs return
typed errors, including stale typed roots, source-order mismatches, unsafe
initializer edges, unsupported visibility/modifiers, and bounded item/owner
chain violations.
